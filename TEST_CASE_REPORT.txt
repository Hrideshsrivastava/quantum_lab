FIX DETAILS
───────────
  TC-2 + TC-14 │ 404 Error Page
  ─────────────┴───────────────────────────────────────────────────────────
  File Created  : 404.html
  Description   : New branded 404 error page matching the Quantum Lab design
                  system. Features animated error code, direct module navigation
                  shortcuts (Theory / Algorithms / Applications / QKD / Bomb /
                  MZI), "Return Home" CTA, and particle canvas background.
                  Any invalid URL now renders this page instead of a blank screen.


  TC-4          │ Gate Applied Before Bloch Scene Initialises
  ─────────────┴───────────────────────────────────────────────────────────
  File Modified : bloch.html
  Changes       :
    • Added isBlochReady = false flag (top of script block).
    • Added a spinning loader overlay (position: absolute over the 3D canvas)
      that is visible until Three.js scene fully initialises.
    • applyGate() now returns early with a toast message if !isBlochReady.
    • After animate(0) is called, isBlochReady = true and the overlay fades
      out smoothly (opacity transition 0.5s) then is removed from DOM.
    • showBlochToast() helper added for consistent error feedback UX.


  TC-6          │ Play Clicked Without Algorithm Selected
  ─────────────┴───────────────────────────────────────────────────────────
  File Modified : algorithms.html
  Changes       :
    • play() now checks if currentAlgo is truthy.
    • If not set, shows toast: "Please select an algorithm tab before running".
    • showToast() utility function added to algorithms.html script.


  TC-8          │ Graph Mode with Only One Algorithm Selected
  ─────────────┴───────────────────────────────────────────────────────────
  File Modified : algorithms.html
  Changes       :
    • play() now checks if currentAlgo === 'graph' and whether both
      currentGraphQ and currentGraphC are set.
    • If either is missing, shows toast: "Select both a Quantum and a
      Classical graph algorithm first."


  TC-10         │ Invalid N Input (Out-of-Range or Non-Numeric)
  ─────────────┴───────────────────────────────────────────────────────────
  File Modified : algorithms.html
  Changes       :
    • validateN(input) function added; checks 8 ≤ N ≤ 32 (integer).
    • N input gains CSS class .invalid on bad input → red border + glow.
    • #nValidMsg span "⚠ Use 8–32 (step 4)" appears inline next to the field.
    • Toast notification shown alongside inline error.
    • play() calls validateN() first and blocks execution if invalid.


  TC-12         │ N Input Change Doesn't Update Simulation
  ─────────────┴───────────────────────────────────────────────────────────
  File Modified : algorithms.html
  Changes       :
    • N input handler changed from onchange (fires only on blur after change)
      to oninput (fires on every keystroke/spinner click immediately).
    • Handler now calls: oninput="validateN(this); resetSim()"
    • Output now updates in real time as the user types/adjusts N.


  TC-16         │ QKD Submit Without Completing Transmission
  ─────────────┴───────────────────────────────────────────────────────────
  File Modified : qkd.js
  Changes       :
    • isTransmissionComplete: false flag added to qkdLab object.
    • Flag reset to false at start of each setupTransmission() call.
    • Flag set to true just before showAnalysisPhase() is called (after all
      100 photons have been sent).
    • selectEve() now checks isTransmissionComplete; shows alert if false.
    • submitDecision() now checks isTransmissionComplete; shows descriptive
      alert before any other logic runs.
    • Alert messages clearly explain what the user needs to do.


  TC-18         │ Bomb Game Invalid Actions
  ─────────────┴───────────────────────────────────────────────────────────
  File Modified : bomb-game.js
  Changes       :
    • sendPhotons() replaced silent early return with four named alerts:
        – No channel selected
        – Round not active
        – Channel already locked
        – Channel already exploded
    • lockDecision() replaced silent early return with three named alerts:
        – No channel selected
        – Channel already locked
        – No photons sent yet (cannot decide without data)
    • Each alert uses ⚠ prefix for visual consistency.
    • Guards prevent unexpected behavior from out-of-order game actions.
